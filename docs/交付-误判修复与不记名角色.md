## 一、Bug「任务自然结束依然收到继续完成工作的提示」— 已修复并上线

### 根因（实证闭环）
pg 会话任务 17:23:45 自然收尾，产出的 9router 分析报告里引用了历史失败（`429 FreeUsageLimitError`）。`wt-live` 上 workflow-engine（pipeflow daemon）的 rate-recovery 扫 pane 末 20 行时把**报告里的引用**误判成活限流，17:24:05 / 17:25:37 两次向已收尾会话发「上一轮 API 错误中断。继续…」，角色被迫重做已完成的请求。

该函数自己的 docstring 就写着正确语义：「错误之后只要再来一条正常轮，就说明已自愈，不许再打断它」——pane 文案 OR 分支恰好绕过它；而 pane 判据自身实测只认出 0.67% 的错误轮（1342 条里 9 条）。

### 修法
1. **触发只认转录错误轮**（`_transcript_last_turn_is_api_error`），pane 文案只保留给配额/瞬时/终态分型；
2. 判定扩展 `_turn_text_starts_with_error`：未标记但整轮正文以 `API Error:` 等开头的（流中断形态）也算错误轮；**只认开头不认包含**——引用错误文案的正常报告轮不算。
